# Discovery: How We Do User Research

> *"The biggest risk in product isn't shipping slowly — it's shipping the wrong thing confidently."*
> — **Marty Cagan**

We use the **Double Diamond** method: first diverge to understand the problem, then converge to define it. Only then do we design and test solutions.

## Why We Research

| Goal | Risk if we skip | How we mitigate |
|---|---|---|
| **Understand real needs** | Build something people don't want | Survey + interview via unbiased panel (Lyssna) |
| **Test ideas early** | Waste resources on solutions that fail | Prototype + user test quickly, use AI for prototypes |
| **Get unbiased feedback** | Build for friends, hear what we want to hear | User testing with people we don't know |
| **Align with real value** | Deliver low-value solutions | Validate before building |

## Research Decision Tree

Pick the method based on what you need to learn:

| When | Method | Tool |
|---|---|---|
| **Validating assumptions with unknown users** | Unbiased panel survey | Lyssna |
| **Deep discovery with existing users** | Interviews | Granola (+ Fireflies if need audio) |
| **Quick feedback on feature** | Super user outreach | WhatsApp group |
| **Testing prototypes** | Usability testing | Lyssna or direct sessions |
| **Quantitative validation** | In-app survey | Typeform |

## Discovery Phase Steps

### 1. Discover
- Survey to validate assumptions on pains and needs
- Send to current users (aim: 100 sent, 50 received)
- Channels: WhatsApp, Typeform contacts, email

### 2. Define
- 10 follow-up interviews based on survey answers
- Create mockups/prototypes
- Define requirements for design

### 3. Design
- Iterate on design, create prototype
- Conduct usability research
- Define requirements for development

## Interview Process

**Before:** Gather insights in Miro, write down assumptions, set up validation plan, competition analysis.

**During:** Schedule via Calendly or direct. Record with Granola (primary) or Fireflies. Transcripts to NotebookLM.

**After:** Analyze results, create user journey map, define follow-up questions, add insights as evidence to IDEA Board items.
