Care Brain MVP: Three Delivery Approaches

3 months, full nervous system, AI-first development. Click to select.

A

Infrastructure-First

Month 1: Build the full nervous system skeleton (event bus, profile store, worker framework, API layer) + run UX research in parallel

Month 2: Build all 6 pipelines on the infrastructure + implement designs

Month 3: Integration, polish, testing, sharing adaptation

Pros

  • Clean architecture from day 1
  • No rework when adding pipelines
  • Infrastructure decisions made upfront

Cons

  • No visible product for 5+ weeks
  • Risk of over-engineering infra
  • UX feedback comes late
  • Big integration risk in month 2
B

Vertical Slices + AI Agents  RECOMMENDED

Slice 1 (Wk 1-4): Recording → Summary → Suggestions → Q&A (the core brain, end-to-end)

Slice 2 (Wk 5-8): Health Profile Store + Voice Input + Document Processing

Slice 3 (Wk 9-11): Appointment Prep + Sharing Adaptation preview

Polish (Wk 12): Integration testing, UX polish, quality gates

Team model: AI coding agents build each slice. Human architect sets patterns in Slice 1. Human reviewers gate each slice. UX research runs 1 sprint ahead. Design runs 1 sprint ahead of engineering.

Pros

  • Working brain from week 4
  • Each slice is testable and demoable
  • Natural priority order (most valuable first)
  • Infrastructure grows with real needs
  • Fast feedback, early course corrections

Cons

  • Some infrastructure rework between slices
  • Requires strong architectural vision upfront
C

Full Parallel Blast

Week 0: Architecture sprint, define all interfaces

Weeks 1-8: All pipelines built simultaneously by different AI agents in isolated worktrees

Weeks 9-12: Integration, UX, polish

Team model: Multiple AI agents work in parallel on independent pipelines. Human orchestrator manages integration.

Pros

  • Theoretically fastest delivery
  • Maximizes AI parallelism
  • Each pipeline is independent

Cons

  • Massive integration risk in weeks 9-12
  • No user-testable product until late
  • Interface mismatches between parallel work
  • UX is bolted on rather than designed in
  • Hardest to course-correct

Why B?

The nervous system architecture is inherently slice-friendly: each pipeline is independent, the event bus and profile store grow incrementally. Slice 1 forces the hardest architectural decisions (event bus, worker pattern, profile schema) with the highest-value feature (Smart Suggestions). By week 4 you have a product you can touch. AI agents handle implementation throughput; humans handle judgment calls at gates. The infrastructure "rework" in Approach B is minimal because the event-driven pattern is naturally additive.
